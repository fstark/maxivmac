# imgutil — Disk Image Utility

A command-line tool for inspecting, extracting, and assembling classic
Macintosh disk images (APM format).

## Goals

1. **Identify** whether a file is an APM disk or a raw HFS partition,
   and display its structure.
2. **Extract** a partition from an APM disk image to a standalone file.
3. **Assemble** one or more raw HFS partition images into a bootable
   APM disk (with driver).

## Supported Formats

| Format | Detection |
|--------|-----------|
| APM disk | DDR signature `ER` (0x4552) at byte 0, `PM` entries at block 1+ |
| Raw HFS partition | MDB signature 0x4244 at byte offset 1024 |

Out of scope: DC42 floppies, MFS, ISO 9660, DiskDup+, DART.

---

## Subcommands

### `imgutil info <file>`

Display disk/partition structure.  For APM disks, shows the DDR, driver
descriptor, and each partition entry.  For HFS partitions nested inside
a disk (or standalone), reads the MDB to show the volume name and dates.

Output format — APM disk:

```
file.img: APM disk (40,000 KB, 80000 blocks × 512)
  Driver: Apple_Driver43 at block 64 (19 blocks, 68000)
  Partitions:
    1: "MacOS"      Apple_HFS          block 96, 79872 blocks (39,936 KB)
       Volume: "System 7.1" (created 1993-01-15, modified 1993-06-20)
    2: "Apple"      Apple_partition_map block 1, 63 blocks
    3: "Macintosh"  Apple_Driver43     block 64, 32 blocks
    4: "Extra"      Apple_Free         block 79968, 32 blocks
```

Output format — raw HFS partition:

```
file.hfs: HFS partition (400,000 KB)
  Volume: "System 7.1" (created 1993-01-15, modified 1993-06-20)
```

### `imgutil extract <file> <index> [-o output]`

Extract partition number `<index>` (1-based, matching `info` output)
from an APM disk image.  Any partition type can be extracted.

Default output filename: `<basename>_p<N>.hfs`

### `imgutil mkdisk <part1> [part2 ...] [-o output]`

Assemble one or more raw HFS partition images into a bootable APM disk.

Each input is validated: must have a valid HFS MDB (signature 0x4244 at
byte 1024).  The tool reads the volume name from the MDB and uses it as
the partition name in the map.  Falls back to "Untitled N" if MDB cannot
be read.

Partition order follows argument order.

Default output: `<basename>_disk.img` (single input).  `-o` is required
when multiple inputs are given.

## Disk Layout (mkdisk output)

Replicates the structure of a known-good Apple HD SC Setup disk:

| Blocks | Content |
|--------|---------|
| 0 | DDR (signature `ER`, block size 512, driver table with 1 entry) |
| 1–63 | Partition map entries (Apple_partition_map, Apple_Driver43, Apple_HFS ×N, Apple_Free) |
| 64–95 | Apple_Driver43 (SCSI driver, 32 blocks allocated, 19 blocks used) |
| 96+ | HFS partitions, packed contiguously |
| tail | Apple_Free (32 blocks) |

Total disk size = 96 + sum(partition sizes) + 32 blocks.

### Driver

The Apple_Driver43 blob is extracted from a known-good System 6 disk
image and stored as `tools/imgutil/driver43.bin`.  It is embedded into
the binary at build time via `xxd -i`.

DDR driver table entry: block 64, size 19 blocks, type 1 (MacOS 68000).

## Build

- Language: C++23
- Single source file: `tools/imgutil/imgutil.cpp`
- Built via CMake (target added to root `CMakeLists.txt`)
- No dependencies on `src/` — fully self-contained
- `driver43.bin` → `driver43_data.h` generated by `xxd -i` custom command

## Testing

Self-bootstrapping shell script:

1. Create a minimal raw HFS image (~32 KB): valid boot blocks + MDB +
   zeroed allocation bitmap.
2. `imgutil mkdisk mini.hfs -o test_disk.img`
3. `imgutil info test_disk.img` — verify output against expected.
4. `imgutil extract test_disk.img 1 -o extracted.hfs`
5. `diff extracted.hfs mini.hfs` — must be identical.

No large binary fixtures in the repository.
